연동 방식
배경
판매자 문의 : 블로그페이 상품을 Meta(페이스북·인스타그램) 카탈로그에 자동으로 등록하고, 가격·품절·판매중지도 반영하고 싶음
1차 적용
피드URL 방식 (개발팀 검토 2안)
블로그페이는 쇼핑몰별 상품 피드URL만 제공합니다. 카탈로그 생성과 피드URL 등록은 판매자가 Meta 커머스 관리자에서 직접 진행하고, Meta가 등록된 주기(최소 1시간)에 맞춰 피드를 가져갑니다.
최종 목표
FBE + 배치 API (개발팀 검토 1안)
판매자가 Meta 계정을 한 번 연결하면 픽셀·카탈로그 설정이 자동으로 되고, 상품이 바뀔 때마다 바로 전송합니다. Meta 담당자 협의·허용 리스트 등록·앱 검수가 먼저 필요해 1차 범위에서 제외합니다.
전환 대비
피드의 상품 id는 상품번호로 고정해 2차 전환 후에도 같은 상품으로 인식되게 합니다.
2차 전환 시 판매자에게 기존 피드 데이터 소스 삭제를 안내합니다. (두 방식을 함께 쓰면 상품이 중복·충돌함, 카페24 안내 기준)
사전 조건
[포털사이트(SNS) 연동 설정]의 페이스북 메타태그(도메인 인증)와 페이스북 픽셀ID 입력. 카탈로그를 만들 때 픽셀의 데이터 세트를 연결합니다. (기존 기능, 신규 개발 없음)
문의 대응
  1. 자동 연동·피드URL 제공 : 피드URL 방식으로 지원
  2. 가격·품절·판매중지 반영 : 피드 갱신과 Meta 수집 주기에 따라 반영
  3. 상품 링크 : 단축주소(bp2.kr) 대신 쇼핑몰 상품 상세 주소 사용
상품 피드 정책
기준
블로그페이 상품정보를 기준으로 보냅니다. 상품 1개 = 피드 1행이며, 옵션 조합별로 나누지 않고 옵션값은 보내지 않습니다.
반영 흐름
상품 등록·수정·삭제 → 피드 다시 만들기 (1시간마다) → Meta 수집 (판매자가 정한 주기, 매시간 안내) → 카탈로그 반영
업로드 방식
바꾸기 : 피드에 없는 상품은 다음 수집 때 카탈로그에서 삭제됩니다. 커머스 관리자에서 피드URL로 카탈로그를 만들면 기본값이 바꾸기입니다.
피드 제외
전시안함·삭제 상품, 아래 필수 값이 없는 상품
Meta 카탈로그 필드블로그페이 상품정보처리 기준
id *상품번호판매자가 바꿀 수 있는 상품코드는 쓰지 않습니다.
item_group_id-보내지 않습니다. 옵션 상품도 대표 상품 정보 1행만 보냅니다.
title *상품명 *그대로 보냅니다.
description *추가 상품 설명값이 없으면 피드에서 제외합니다. 화면 안내 배너에서 필수 입력을 안내합니다.
availability *품절여부블로그페이 품절 기준을 따릅니다. 판매 → in stock / 품절 → out of stock
condition *-new로 고정합니다.
price * / sale_price이전 판매가 / 판매가 *이전 판매가가 판매가보다 크면 price = 이전 판매가, sale_price = 판매가. 아니면 price = 판매가. 형식 : 1000 KRW
link *상품 URL쇼핑몰 상품 상세 주소를 보냅니다. 단축주소(bp2.kr)는 쓰지 않습니다.
image_link *대표 이미지그대로 보냅니다.
brand *브랜드 / 제조사 / 상점명브랜드가 없으면 제조사, 제조사도 없으면 상점명을 보냅니다.
google_product_category-보내지 않습니다.

화면 설명
쇼핑 DBURL 설정(Beta) 아래에 Meta 카탈로그 피드URL 설정 영역을 추가합니다. 판매자는 여기서 받은 피드URL을 Meta 커머스 관리자에 직접 등록합니다.
  1. 1
    Meta 카탈로그 피드URL 설정
    • 다른 연동 영역처럼 펼치고 접을 수 있습니다.
    • 오른쪽에 설정 상태(사용 / 사용안함)를 표시합니다.
  2. 2
    안내 배너
    • 이용 대상, 설정 방법, 반영 기준, 필수 항목을 안내합니다.
    • 배너 문구
  3. 3
    피드URL 설정
    • 기본값은 사용안함입니다.
    • 사용함 상태에서 사용안함을 고르면 확인 알림이 뜹니다.
  4. 4
    버튼 - 도움말
    • 누르면 Meta 카탈로그 피드URL 설정방법 모달이 열립니다.
    • 단계별 설정 방법은 정책 확정 후 작성합니다.
    • 모달 상단 문구
  5. 5
    피드URL 경로
    • 사용함으로 저장하면 보입니다. 읽기 전용입니다.
    • 경로가 만들어지기 전에는 안내 문구를 보여 줍니다.
  6. 6
    버튼 - 도메인 변경
    • 쇼핑 DBURL의 [도메인 변경]과 같습니다.
  7. 7
    버튼 - 저장
    • 입력한 설정을 저장합니다.
    • 사용안함에서 사용함으로 저장하면 알림이 뜨고 피드URL 경로를 만들기 시작합니다.
  1. 1
    알림 - 저장
    • 사용안함에서 사용함으로 저장하면 노출됩니다.
    • 확인을 누르면 피드URL 경로 생성 대기 화면이 보입니다.
    • 알림 문구
  2. 2
    버튼 - 저장
    • 알림이 뜨는 버튼입니다.
  1. 1
    알림 - 사용안함 선택
    • 사용함 상태에서 사용안함을 고르면 노출됩니다.
    • 확인을 누르면 사용안함이 선택되고, 취소하면 사용함을 유지합니다. 저장해야 적용됩니다.
    • 알림 문구
  2. 2
    피드URL 설정
    • 알림이 뜨는 선택지입니다.
위치
외부서비스 연동의 쇼핑 DBURL 설정(Beta) 아래에 Meta 카탈로그 피드URL 설정 영역을 추가합니다.
기본값
피드URL 설정 사용안함
피드URL 경로
사용함으로 저장하면 만듭니다. 생성은 최대 하루까지 걸리며, 쇼핑몰마다 1개입니다.
사용안함 전환
피드URL의 상품 정보 갱신을 멈춥니다. Meta 커머스 관리자의 데이터 소스는 판매자가 직접 삭제합니다.
도메인 변경
쇼핑 DBURL의 [도메인 변경]과 같습니다.
사전 조건 안내
페이스북 메타태그·픽셀ID 입력은 안내 배너와 도움말로 안내합니다.
도움말
Meta 커머스 관리자 설정 방법을 모달로 안내합니다. 단계별 내용은 정책 확정 후 작성합니다.
피드URL 보호
피드URL을 누구나 열 수 있게 둘지, 토큰·로그인 정보로 막을지 개발팀 확인 필요. 막는 경우 도움말의 Meta 등록 단계 안내가 달라짐
피드 생성 주기·구조
1시간마다 다시 만들기가 가능한지, 쇼핑 DBURL 생성 구조를 재사용할 수 있는지 개발팀 확인 필요
사용안함 후 피드 응답
사용안함 후 피드URL이 빈 목록을 주면 바꾸기 업로드로 카탈로그 상품이 모두 삭제되고, 오류를 주면 상품이 남음. 어느 쪽으로 할지 결정 필요
개인 도메인
개인 도메인을 연결한 쇼핑몰에서 피드URL과 상품 링크(link)에 연결 도메인을 쓰는지 개발팀 확인 필요
픽셀 상품 id
기존 페이스북 픽셀 이벤트가 보내는 상품 id가 피드 id(상품번호)와 같은지 개발팀 확인 필요. 다르면 카탈로그 광고의 상품 매칭이 안 됨
브랜드 값
브랜드는 상품등록 API에는 있으나 상품 상세 API 응답에는 없음. 피드에 쓸 수 있는지 개발팀 확인 필요
주문서만 전시 상품
쇼핑몰 상세 페이지가 없어 상품 링크를 만들 수 없음. 피드에서 제외할지 결정 필요
추가 상품 설명 = 상품명
Meta는 설명이 상품명과 같으면 안 됨. 같은 값일 때 제외할지 그대로 보낼지 결정 필요
판매기간 외 상품
판매기간 시작 전·종료 후 상품을 블로그페이 기준으로 품절로 볼지 확인 필요
메타태그·픽셀ID 미입력
미입력 상태에서 사용함 저장을 막을지, 배너 안내만 할지 결정 필요
옵션 상품
Meta는 의류·신발 등에서 size를 요구함. 옵션 미전송 상품이 Shop에서 경고·거절되는지 테스트 업로드 후 확인 필요
BASIC
BASIC 관리자에도 같은 설정을 둘지 결정 필요
